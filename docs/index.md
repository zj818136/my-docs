## 实践体会

这次实践第一次把"写文档"和"发布"串成了一条完整的流水线。以前写完 Markdown 只能放在本地，或者手动打包上传，改一个字就要重走一遍流程；现在只要把改动推送到 `main` 分支，Actions 就会自动安装依赖、执行构建、上传 `site/` 产物，并由官方 Pages 部署动作发布到站点，全程不用人守着。

印象最深的是排错。最初部署后页面样式全丢、只剩纯文字，翻了 Actions 日志才发现构建产物没有正确发布到 Pages，资源路径也对不上。我先后试过分支发布、第三方 gh-pages 发布，最后回到课程要求的官方 Pages Actions 流程，才把"源码 → site/ → 站点"这条链路理清楚。这也让我确认了一件事：文档源码、构建产物和托管服务是三件不同的事，出问题时要先判断卡在哪一环。
